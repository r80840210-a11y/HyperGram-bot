# XyperGram bot

Render service type: Web Service
Build: `pip install -r requirements.txt`
Start: `python bot.py`

Environment:
- BOT_TOKEN: BotFather token
- DB_PATH: xypergram.db
- WEBHOOK_SECRET: shared webhook secret (optional but recommended)
- PHONE_POOL_RU: JSON array of provider-assigned numbers, e.g. `["+7..."]`
- PHONE_POOL_US: JSON array of provider-assigned numbers, e.g. `["+1..."]`

The service listens on `0.0.0.0:$PORT`, with GET /health.

Configure your SMS provider to POST to:
`https://YOUR-RENDER-SERVICE.onrender.com/provider-webhook`
JSON body:
`{"service":"xypergram","phone":"+1...","message":"Your XyperGram verification code is 123456"}`
If WEBHOOK_SECRET is set, send header `X-Webhook-Secret` with that value.
Map the provider's documented webhook fields to this format. This handler is only for messages generated by your own XyperGram registration service, not codes for Telegram or other third-party accounts.

Only one active number per user; an active phone cannot be assigned to another user. Numbers are randomly selected from provider-provisioned inventory; the app does not fabricate phone numbers.
Stop any other process polling the same Telegram bot token to avoid TelegramConflictError.
SQLite on Render's ephemeral disk may be lost after restart/redeploy; use PostgreSQL or a persistent disk for durable storage.
